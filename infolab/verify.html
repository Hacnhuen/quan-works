00为什么要做交叉检验

AI 生成的学习材料有三类典型失效，且它们互不重叠——所以需要三条独立轨道，而不是一个笼统的"检查一下"。

失效类型 1

数学错误

公式写反、条件遗漏、证明跳步、极限情形不成立。表面上"看起来很专业"，实际推不出来。由 AI-Science 轨捕获。

失效类型 2

出处幻觉

定理归错人、年份写错、引用不存在的论文、把综述里的转述当原始文献。这是 LLM 最高频的错误类型。由 AI-学术轨捕获。

失效类型 3

伪解释

句子全对但读者学不到东西——同义反复、术语堆砌、缺少具体数字与反例。由 AI-费曼轨捕获。

关键设计：三轨必须独立 如果用同一个模型、同一段提示词一次性"检查全部问题"，它会倾向于给出笼统的肯定回答（谄媚偏差）。三轨的价值在于判据互斥、各自可独立否决：一条内容可以数学正确但出处错误，也可以出处完整但读者读不懂。任何一轨判 FAIL 都必须修改后重检。

01三轨判据（12 项）

Track A · AI-Science · 数学与科学严谨性
  1. A1 陈述完整性：定理是否写全了成立条件？（i.i.d.？有限字母表？平稳遍历？凸性？）遗漏条件一律判 FAIL。
  2. A2 证明可追踪：每一步是否只依赖已在本站更早层级出现过的结论？出现"显然""易证"跳过关键步骤判 WARN。
  3. A3 极限自洽：把参数推到边界（p→0、n→∞、ε→0.5、D→0）后，公式是否退化为已知的正确形式？
  4. A4 数值可核：所有给出的数字（如 C=0.531、E=1.69、kBT ln2=2.87e−21 J）是否能独立算出？
  5. A5 量纲与单位：bit / nat / bit-per-symbol / bit-per-second 是否全程一致且标注清楚？
Track B · AI-学术 · 文献与出处
  1. B1 首创归属：定理归属的人名、年份是否为原始出处而非二手转述？
  2. B2 出版信息：期刊/会议名称、卷号、页码是否可核？无法核实的引用必须降级为"据 X 综述"。
  3. B3 共识状态：该结论是教科书共识、活跃争议，还是单篇论文的主张？必须显式标注。
  4. B4 反方呈现：存在实质性反驳的条目，是否同时引用了反驳方？只引一侧判 FAIL。
Track C · AI-费曼 · 可解释性
  1. C1 无术语循环：能否在不使用被定义术语本身的前提下解释它？（"熵是信息的度量，信息是熵所度量的东西"= FAIL）
  2. C2 具体数字：是否至少有一个可以手算的具体例子，而非纯符号推演？
  3. C3 反例或边界：是否说明了"什么时候不成立"？只讲成立情形判 WARN。
判定等级 PASS 全部判据通过 · NOTE 通过，附补充说明 · WARN 有可改进项，不影响正确性 · FAIL 必须修改后重检（本站不保留 FAIL 状态的内容上线）

03已发现并修正的问题

这一节是本页最有价值的部分。一份从不报告错误的检验报告，本身就是不可信的。以下是检验过程中实际拦截并修正的问题。

修正 #1 · A1 陈述完整性 · 严重

问题：初稿在 L2 写"Shannon 第二定理：R < C 时误差概率可任意小"，未说明这是平均误差概率还是最大误差概率，也未说明适用于 DMC。

为什么严重：随机编码论证直接得到的是平均误差概率小；要得到最大误差概率小，需要额外的"扔掉最差一半码字"步骤（码率损失可忽略）。跳过这一步是教材中常见的隐性漏洞。

修正：L2 正文补入"离散无记忆信道"前提，并在证明第 5 步显式加入 expurgation（去劣码字）论证。

修正 #2 · B4 反方呈现 · 严重

问题：初稿在 L4 只引用 Shwartz-Ziv & Tishby (2017)，把"压缩相解释泛化"写成了既定结论。

为什么严重：这是当前深度学习理论中最著名的未决争议之一。单侧引用会让读者形成错误的共识判断，且这个错误在后续阅读论文时会持续误导。

修正：L4 §04 新增 Saxe et al. (ICLR 2018) 完整反驳三条（激活函数依赖 / binning 伪影 / 无因果证据），加入 VIB 与 V-information 的和解路线，并在正文加"学术诚实声明"框。检验矩阵标注为争议条目。

修正 #3 · A3 极限自洽 · 中等

问题：初稿描述 BSC 容量时写"ε 越大容量越低"。

为什么错：ε=1（总是翻转）时容量是 1，不是 0。C(ε)=1−H₂(ε) 关于 ε=0.5 对称，在 ε>0.5 时容量反而回升。

修正：改为"ε 越接近 0.5 容量越低"，并在实验室 05 用可拖动滑块让读者亲自撞见 ε=1 时容量回到 1 的反直觉现象。

修正 #4 · B1 首创归属 · 中等

问题：初稿把 Kraft 不等式整体归给 Kraft (1949)。

为什么不准确：Kraft 1949 证明的是"对前缀码成立"；McMillan (1956) 才把它推广到全部唯一可译码——后者才是"前缀码不损失最优性"这一重要推论的来源。

修正：L1 §07 拆分为 Kraft 不等式与 Kraft–McMillan 定理两条，分别标注出处。

修正 #5 · B3 共识状态 · 中等

问题：初稿把神经缩放律 L = E + A/N^α + B/D^β 与 Shannon 三定理并列为"定理"。

为什么错：缩放律是经验拟合，没有证明，且拟合系数依赖数据集、架构与训练配方；Chinchilla 论文本身就修正了 Kaplan 的早期系数。把它称为定理会误导读者对其可靠性的判断。

修正：标题改为"定理/经验律 T38"，正文明确标注"经验拟合，非定理"，并在检验矩阵给 NOTE。

修正 #6 · A4 数值可核 · 轻微

问题：初稿称 Landauer 极限"约 3×10⁻²¹ J"，未给温度。

为什么要改：kBT ln2 与温度成正比，不给 T 的数值毫无意义。

修正：改为"kBT ln2 ≈ 2.87 × 10⁻²¹ J（T = 300 K）≈ 0.0179 eV ≈ 0.7 kBT"，三种单位互校。

修正 #7 · C3 反例或边界 · 轻微

问题：初稿讲信源信道分离定理时只说"可以分开设计而不损失最优性"。

修正：补入边界条件——该定理对点对点信道成立；在多用户网络（如 MAC 传相关信源）中一般不成立，联合信源信道编码严格更优。这直接关系到读者是否会在实际系统设计中误用。

检验报告若不可复跑，就只是一份声明。以下是完整的四阶段流水线，任何人可以在本地对本站（或自己的材料）重跑。

阶段 0 抽取 从 HTML 抽出全部 .el-theorem / .el-proof / .el-formula 块 → claims.json ↓ 阶段 1 自动检查 数值重算 · 极限自洽 · 单位一致 · 内部引用完整性 ← 纯脚本，无需模型 ↓ 阶段 2 三轨审查 A/B/C 三条独立提示词，各跑一次，产出结构化判定 ↓ 阶段 3 汇总 合并三轨结果 → report.md + 更新检验矩阵 ↓ 任一轨 FAIL → 回到内容修改 → 重跑阶段 1–3
阶段 0 · 抽取声明（verify/extract.py） 
#!/usr/bin/env python3
"""从 infolab/*.html 抽取待检验声明，输出 claims.json。"""
import json, re, pathlib
from html.parser import HTMLParser

KINDS = {
    "el-theorem": "theorem", "el-proof": "proof", "el-coro": "corollary",
    "el-formula": "formula", "el-frontier": "frontier",
}

class Extract(HTMLParser):
    def __init__(self):
        super().__init__()
        self.depth = 0
        self.kind = None
        self.buf = []
        self.out = []

    def handle_starttag(self, tag, attrs):
        cls = dict(attrs).get("class", "")
        if self.kind is None:
            for k, name in KINDS.items():
                if k in cls:
                    self.kind, self.depth, self.buf = name, 1, []
                    return
        elif tag == "div":
            self.depth += 1

    def handle_endtag(self, tag):
        if self.kind and tag == "div":
            self.depth -= 1
            if self.depth == 0:
                text = re.sub(r"\s+", " ", "".join(self.buf)).strip()
                if text:
                    self.out.append({"kind": self.kind, "text": text})
                self.kind = None

    def handle_data(self, data):
        if self.kind:
            self.buf.append(data)

claims = []
for f in sorted(pathlib.Path(".").glob("*.html")):
    p = Extract()
    p.feed(f.read_text(encoding="utf-8"))
    for i, c in enumerate(p.out):
        c["id"] = f"{f.stem}#{c['kind']}{i:02d}"
        c["page"] = f.name
        claims.append(c)

pathlib.Path("verify/claims.json").write_text(
    json.dumps(claims, ensure_ascii=False, indent=2), encoding="utf-8")
print(f"extracted {len(claims)} claims from {len(set(c['page'] for c in claims))} pages")
阶段 1 · 自动数值检查（verify/numeric.py）

这一阶段完全不用模型，纯脚本即可捕获很大一部分错误——性价比最高，应当先跑。

#!/usr/bin/env python3
"""独立重算全站出现的关键数值，与页面中写的值比对。"""
from math import log2, log, exp, sqrt, pi

def h2(p):
    return 0.0 if p in (0, 1) else -p*log2(p) - (1-p)*log2(1-p)

CHECKS = []
def check(name, got, want, tol=5e-4):
    ok = abs(got - want) <= tol * max(1.0, abs(want))
    CHECKS.append((name, got, want, ok))

# --- L1 ---
check("H2(0.5)",            h2(0.5),            1.0)
check("H2(0.1)",            h2(0.1),            0.4690, 2e-3)
check("H2(0.11)",           h2(0.11),           0.4999, 2e-3)
check("BSC(0.1) capacity",  1 - h2(0.1),        0.5310, 2e-3)
check("BSC(0.11) capacity", 1 - h2(0.11),       0.5000, 2e-3)
check("log2(3)",            log2(3),            1.5850, 1e-3)

# --- L1 Shannon-Hartley: 20dB, 20MHz ---
snr = 10 ** (20/10)
check("SH C (20dB,20MHz) Mbps", 20*log2(1+snr), 133.15, 1e-2)
check("Shannon limit Eb/N0 dB", 10*log(log(2))/log(10), -1.5917, 1e-3)

# --- L3 rate-distortion ---
check("R(D) bern p=.5 D=.1", h2(0.5)-h2(0.1),   0.5310, 2e-3)
check("gauss 1 bit = 6.02dB", 10*log(4)/log(10), 6.0206, 1e-3)

# --- L4 quantum: depolarizing d=2 p=0.2 ---
check("depol chi* (d=2,p=.2)", 1 - h2(0.1),     0.5310, 2e-3)

# --- L4 Landauer at 300K ---
kB = 1.380649e-23
check("kB*T*ln2 @300K (J)", kB*300*log(2),      2.8703e-21, 1e-3)
check("  same in eV",       kB*300*log(2)/1.602176634e-19, 0.017916, 1e-3)

# --- L4 Chinchilla ---
E, A, al, B, be = 1.69, 406.4, 0.3392, 410.7, 0.2849
L = lambda N, D: E + A/N**al + B/D**be
check("Chinchilla L(70e9, 1.4e12)", L(70e9, 1.4e12), 1.99, 3e-2)
check("  E in bits/token",          E/log(2),        2.4383, 1e-3)

# --- L4 maxent dice, mean 4.5 ---
def dice_mean(lam):
    z = sum(exp(lam*k) for k in range(1, 7))
    return sum(k*exp(lam*k) for k in range(1, 7)) / z
lo, hi = -5.0, 5.0
for _ in range(200):
    mid = (lo+hi)/2
    lo, hi = (mid, hi) if dice_mean(mid) < 4.5 else (lo, mid)
lam = (lo+hi)/2
z = sum(exp(lam*k) for k in range(1, 7))
ps = [exp(lam*k)/z for k in range(1, 7)]
Hd = -sum(p*log2(p) for p in ps)
check("maxent dice lambda", lam, 0.3710, 5e-3)
check("maxent dice H",      Hd,  2.3955, 5e-3)

bad = [c for c in CHECKS if not c[3]]
for name, got, want, ok in CHECKS:
    print(f"{'PASS' if ok else 'FAIL'}  {name:34s} got={got:.6g}  want={want:.6g}")
print(f"\n{len(CHECKS)-len(bad)}/{len(CHECKS)} numeric checks passed")
raise SystemExit(1 if bad else 0)

阶段 1b · 结构与链接检查（verify/structure.py） 
#!/usr/bin/env python3
"""检查：站内链接有效性 · 锚点存在性 · 每页七元素齐备 · 无隐藏内容。"""
import re, pathlib, sys

pages = sorted(pathlib.Path(".").glob("*.html"))
ids   = {p.name: set(re.findall(r'id="([^"]+)"', p.read_text(encoding="utf-8")))
         for p in pages}
errs = []

for p in pages:
    src = p.read_text(encoding="utf-8")

    # 1) 站内链接与锚点
    for href in re.findall(r'href="([^"]+)"', src):
        if href.startswith(("http", "mailto:")):
            continue
        file, _, anchor = href.partition("#")
        target = file or p.name
        if target not in ids:
            errs.append(f"{p.name}: 链接指向不存在的文件 {target}")
        elif anchor and anchor not in ids[target]:
            errs.append(f"{p.name}: 锚点不存在 {target}#{anchor}")

    # 2) 内容页必须含七元素中的核心块
    if p.stem.startswith("l"):
        for need in ("el-concept", "el-theorem", "el-formula", "el-example"):
            if need not in src:
                errs.append(f"{p.name}: 缺少内容块 .{need}")

    # 3) 禁止把内容藏起来（历史事故：opacity:0 的 reveal 动画）
    for pat in (r"opacity\s*:\s*0\b", r"display\s*:\s*none", r"visibility\s*:\s*hidden"):
        for m in re.finditer(pat, src):
            line = src[:m.start()].count("\n") + 1
            errs.append(f"{p.name}:{line}: 检测到可能隐藏内容的样式 `{m.group(0)}`")

    # 4) 引用完整性：出现"定理 Tnn"就应在同页或信源中有出处年份
    for t in set(re.findall(r"定理\s*T(\d+)", src)):
        if not re.search(r"(19|20)\d{2}", src):
            errs.append(f"{p.name}: 定理 T{t} 所在页面未出现任何年份，疑似缺出处")

for e in errs:
    print("FAIL " + e)
print(f"\n{len(pages)} pages checked, {len(errs)} issues")
sys.exit(1 if errs else 0)
阶段 2 · 三轨模型审查（verify/run_tracks.py）

把 claims.json 与三条提示词模板送给三次独立调用。关键约束：不要在同一次对话里跑三轨，否则后一轨会被前一轨的结论锚定。

#!/usr/bin/env python3
"""对每条 claim 跑三轨审查。模型调用留作适配层，可换任意后端。"""
import json, pathlib, sys

PROMPTS = {
    "science":  pathlib.Path("verify/prompt_science.md").read_text(encoding="utf-8"),
    "academic": pathlib.Path("verify/prompt_academic.md").read_text(encoding="utf-8"),
    "feynman":  pathlib.Path("verify/prompt_feynman.md").read_text(encoding="utf-8"),
}

def call_model(system_prompt: str, claim_text: str) -> dict:
    """适配层：接入任意模型后端，要求返回 JSON。
    约定返回 {"verdict": "PASS|NOTE|WARN|FAIL",
              "criteria": {"A1": true, ...},
              "issues": ["..."],
              "fix": "建议的修改"}
    """
    raise NotImplementedError("在此接入你的模型后端")

def main():
    claims = json.loads(pathlib.Path("verify/claims.json").read_text(encoding="utf-8"))
    results = []
    for c in claims:
        row = {"id": c["id"], "page": c["page"], "kind": c["kind"]}
        for track, prompt in PROMPTS.items():
            row[track] = call_model(prompt, c["text"])   # 三次独立调用
        # 取最严格的判定
        order = {"PASS": 0, "NOTE": 1, "WARN": 2, "FAIL": 3}
        row["final"] = max((row[t]["verdict"] for t in PROMPTS), key=lambda v: order[v])
        results.append(row)

    pathlib.Path("verify/results.json").write_text(
        json.dumps(results, ensure_ascii=False, indent=2), encoding="utf-8")

    fails = [r for r in results if r["final"] == "FAIL"]
    print(f"{len(results)} claims checked, {len(fails)} FAIL")
    sys.exit(1 if fails else 0)

if __name__ == "__main__":
    main()

#!/usr/bin/env python3
"""合并三轨结果，生成 report.md 与可粘贴回 verify.html 的矩阵行。"""
import json, pathlib
from collections import Counter

R = json.loads(pathlib.Path("verify/results.json").read_text(encoding="utf-8"))
cnt = Counter(r["final"] for r in R)

lines = ["# InfoLab 交叉检验报告", "",
         f"- 声明总数：{len(R)}",
         f"- PASS {cnt['PASS']} · NOTE {cnt['NOTE']} · WARN {cnt['WARN']} · FAIL {cnt['FAIL']}", ""]

for level in ("FAIL", "WARN", "NOTE"):
    rows = [r for r in R if r["final"] == level]
    if not rows:
        continue
    lines += [f"## {level}（{len(rows)} 条）", ""]
    for r in rows:
        lines.append(f"### `{r['id']}`  ({r['page']})")
        for track in ("science", "academic", "feynman"):
            v = r[track]
            if v["verdict"] != "PASS":
                lines.append(f"- **{track}** → {v['verdict']}")
                for it in v.get("issues", []):
                    lines.append(f"  - {it}")
                if v.get("fix"):
                    lines.append(f"  - 建议：{v['fix']}")
        lines.append("")

pathlib.Path("verify/report.md").write_text("\n".join(lines), encoding="utf-8")
print("wrote verify/report.md")

06三轨提示词模板

提示词的关键不在于"请仔细检查"，而在于给出可否决的具体判据并强制要求指出问题——否则模型会默认给出肯定答复。

verify/prompt_science.md · A 轨 
你是一位信息论方向的审稿人，只负责**数学与科学严谨性**。
不要评价写作风格、不要评价文献引用——那是另外两位审稿人的职责。

逐条核查以下判据，任一条不满足即降级：
A1 陈述完整性：定理成立条件是否写全？（i.i.d. / 有限字母表 / 平稳遍历 /
   离散无记忆 / 凸性 / 正则性）遗漏关键条件 → FAIL。
A2 证明可追踪：每一步是否只依赖更基础的、已陈述的结论？
   出现"显然""易证"却跳过实质步骤 → WARN。
A3 极限自洽：把参数推到边界（p→0,1 / n→∞ / ε→0.5 / D→0 / SNR→0,∞）后，
   公式是否退化为已知正确形式？不自洽 → FAIL。
A4 数值可核：文中所有具体数字，你能否独立算出？算不出或对不上 → FAIL。
A5 量纲一致：bit / nat / bit·符号⁻¹ / bit·s⁻¹ 是否全程一致并标注？

硬性要求：
- 必须至少指出一个可改进点。若确实找不到问题，明确写
  "未发现问题，但以下表述可更精确：…"，不允许只回复"没问题"。
- 对每条判据给出 true/false，不要含糊。

输出严格 JSON：
{"verdict":"PASS|NOTE|WARN|FAIL",
 "criteria":{"A1":true,"A2":true,"A3":true,"A4":true,"A5":true},
 "issues":["…"],
 "fix":"具体的修改建议"}

待审内容：

三条反谄媚设计 ① 强制找茬：A 轨要求"必须至少指出一个可改进点"，堵住"看起来都对"的默认回答。

07本检验的局限（必须写清楚）

不要过度信任这份报告
  1. 模型不是权威。三轨审查能捕获常见错误，但对深层次的、需要真正研究能力才能发现的问题无能为力。一个模型说 PASS，不等于它验证了证明，只等于它没有发现问题。
  2. 共谋失效。如果三轨用的是同一个基础模型，它们可能共享同样的知识盲区与偏见。理想做法是三轨使用不同厂商的模型；本站的实践尚未完全做到这一点。
  3. 出处核查的根本困难。模型无法真正联网核对卷号页码。B 轨能做的是"标记可疑项"，真正的核实需要人去查数据库。unverifiable 字段里的条目都还没有被真正核实。
  4. 前沿部分不确定性最高。L4 涉及 2023–2025 的工作，处于模型知识边界，错误率显著高于 L0–L2。读者引用 L4 内容前应查原文。
  5. 本站的三条预测未经验证。P1/P2/P3 是本站提出的、尚无人复现的陈述。它们的价值在于可被证伪，不在于"很可能对"。
  6. 阶段 2 需要你自己接后端。本页给出的 run_tracks.py 保留了 call_model 适配层未实现——因为绑定特定 API 会让流水线很快过时。阶段 1/1b 是完全可跑的。
改进路线
  • 形式化验证：把 L1–L2 的核心不等式（Gibbs、Jensen、DPI、Fano）用 Lean 4 / Coq 形式化。信息论的核心部分体量适中，是形式化数学的好目标。已有 mathlib 中的部分测度论与熵基础可复用。
  • 数值验证扩展：把阶段 1 从"核对写死的常数"升级为"从页面正则抽取所有数字并重算"，覆盖率从当前约 15 个数值扩到全站。
  • 异构三轨：三条轨道分别使用不同厂商的模型，并记录分歧率——分歧本身就是高价值信号，应优先人工复核分歧条目。
  • 引用数据库对接：B 轨接入 Semantic Scholar / DBLP / arXiv API，把"疑似幻觉引用"变成可自动判定的检查。这是提升最大的一项。
  • 读者反馈闭环：把读者报错纳入检验矩阵，形成持续修订。真实读者是最强的第四条轨道。
