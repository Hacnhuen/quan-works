L0 启蒙：什么是信息

这一级不出现一个积分符号。我们只问一个问题：「知道一件事」到底获得了多少东西？答案会自己长成 −log p。读完你能对任何一个日常事件估算它的信息量。

学段：中学 / 通识门槛：对数 + 概率初步 预计：60–90 分钟核心：惊奇度 · 比特 · 平均

00一个被误解的词

日常语言里，「信息」指内容；信息论里，「信息」指不确定性的减少量。这是理解一切的前提。

Concept 概念

看这两句话：

  • 「明天太阳从东边升起。」
  • 「明天本市下冰雹。」

作为内容，第一句更重要（太阳可是恒星）。但作为信息，第一句几乎为零——你早就知道了，它没有消除任何不确定性。第二句罕见，因此信息量大。

关键转向：信息量不取决于内容多重要，只取决于这件事有多出人意料。

Shannon 的刻意切割 1948 年 Shannon 在论文开篇明确声明：通信的语义方面与工程问题无关（"the semantic aspects of communication are irrelevant to the engineering problem"）。他故意把"意义"扔掉，只留下"概率"。正是这一刀，让信息变成可计算的物理量。
Shannon, A Mathematical Theory of Communication, BSTJ 27(3), 1948.
Frontier 前沿

Shannon 扔掉的"语义"，今天正被捡回来：语义通信（semantic communication）是 6G 的核心议题之一，目标是只传"接收方需要理解的那部分"，而非全部比特。这是 IEEE ITW 2025 的重点方向。→ L4 开放问题

01猜数游戏：信息可以被"数"出来

最快理解信息量的方式，是把它变成"最少问几个是非题"。

Example 例题

我心里想一个 1–8 之间的整数，你只能问"是/否"问题。最少几个问题保证猜中？

笨办法："是 1 吗？""是 2 吗？"……最差要问 7 次。

聪明办法——每次砍掉一半：

问1：大于 4 吗？   → 8 个可能 变 4 个
问2：大于 6 吗？   → 4 个可能 变 2 个
问3：大于 7 吗？   → 2 个可能 变 1 个  ✓ 确定

3 次。因为 2³ = 8。每个是非题最多砍掉一半可能性。

Formula 公式
N 个等可能选项 → 需要 log₂N 个是非题 8 个选项 → log₂8 = 3 题 16 个选项 → log₂16 = 4 题 1024 个 → log₂1024 = 10 题

注意：可能性翻倍，问题只加一。这就是对数出现的原因——它把"乘法的可能性"变成"加法的代价"。

为什么必须是对数？ 因为信息应该可加。抛两枚硬币，直觉上信息量应是抛一枚的 2 倍。但可能性是 2×2=4（相乘），只有取对数才能把"相乘"变"相加"：log₂4 = 2 = 2×log₂2。
Hartley 早在 1928 年就用这个理由确立了对数度量。

02惊奇度：不等概率怎么办

上面假设了"等可能"。但现实中事件概率并不相等——罕见事件应该更"值钱"。

Concept 概念

把 log₂N 改写一下。等可能时每个选项概率 p = 1/N，所以 N = 1/p：

log₂N = log₂(1/p) = −log₂p

这个量叫 自信息（self-information），也可以叫惊奇度（surprisal）。它只依赖那一个事件自己的概率。

Formula 公式
I(x) = −log₂ p(x) 单位：比特 bit
事件概率 p信息量 −log₂p感受
1（必然）0 bit毫不意外，白说
1/21 bit一次硬币
1/83 bit有点意外
1/1000≈ 9.97 bit相当罕见
→ 0（几乎不可能）→ ∞震惊
▶ 交互：惊奇度曲线
0.125
Corollary 推论
  • 必然事件信息量为 0。p=1 时 −log₂1 = 0。所以"太阳东升"确实是 0 bit。
  • 越罕见信息量越大，且是无界的。
  • 独立事件信息量相加。若 x,y 独立，p(x,y)=p(x)p(y)，则 I(x,y) = I(x)+I(y)。

03比特：信息的单位

Concept 概念

1 比特 = 回答一个"五五开"是非题所获得的信息量。

"bit" 这个词是 Shannon 在 1948 年论文中采用的，由他的同事 John Tukey 提议，是 binary digit 的缩写。这篇论文同时给了计算机时代最基本的计量单位。

Formula 公式

换底就换单位，本质相同：

底数单位换算常见场合
2比特 bit / shannon1通信、计算机
e奈特 nat1 nat ≈ 1.4427 bit数学推导、机器学习
10哈特莱 hartley / dit1 hartley ≈ 3.3219 bit早期文献
log₂x = ln x / ln 2 = ln x × 1.442695…
易混：bit（信息量）≠ bit（存储位） 存储上的 1 bit 是一个能存 0/1 的格子。信息论的 1 bit 是一个量，可以是小数——比如某事件信息量 2.7 bit。一个存储位最多携带 1 bit 信息，当且仅当 0/1 等概率时取到。这个"最多"正是 L1 熵极值定理的内容。

04平均惊奇 = 熵

单个事件的信息量会变。要刻画一个"信息源"整体，需要取平均——这就是熵。

Concept 概念

假设天气只有两种，晴 90%、雨 10%。每天你会获得多少信息？

  • 晴天（90% 出现）：−log₂0.9 ≈ 0.152 bit
  • 雨天（10% 出现）：−log₂0.1 ≈ 3.322 bit

按出现频率加权平均：

H = 0.9 × 0.152 + 0.1 × 3.322 = 0.137 + 0.332 = 0.469 bit/天

这个加权平均就是 熵（entropy），记作 H。它衡量这个信息源的平均不确定性。

Formula 公式
H(X) = Σ p(x) · I(x) = − Σ p(x) log₂ p(x)

读作："每个事件的信息量，按它出现的概率加权求和。"

▶ 交互：二元熵函数 H(p)
0.90

拖动看三件事：① p=0 或 1 时 H=0（天气完全确定，毫无信息）；② p=0.5 时 H 最大 =1 bit（最不确定）；③ 曲线对称且是凹的。

Corollary 推论

熵 = 平均每天最少需要多少比特来记录。

上面的天气源熵为 0.469 bit/天。这意味着：记录 1000 天的天气，理论上只需约 469 比特，而不是 1000 比特（每天一位）。省下的一半，来自"晴天多得多"这个规律。

这个"最少"是不可突破的下界——它就是 Shannon 第一定理（无失真信源编码定理）。→ L2 第一定理

为什么它叫"熵"？ 这个名字来自热力学。据 Shannon 本人回忆，是 von Neumann 建议的，理由半是玩笑："第一，你的不确定性函数在统计力学里已经用了这个名字；第二，更重要的是，没人真正知道熵是什么，所以辩论时你总占上风。"
玩笑背后是真的：Shannon 熵与 Boltzmann–Gibbs 熵在数学形式上一致，这条线索最终通向 Landauer 原理与麦克斯韦妖。→ L4 信息与物理

05称球问题：用熵预判难度

信息论最爽的用法之一：还没开始解题，就知道题目解不解得开。

Example 例题

题目：12 个球，其中 1 个是次品（不知偏轻还是偏重）。用天平最少称几次能找出它并判断轻重？

信息论解法（30 秒）：

  1. 算需要多少信息。答案可能是"第 i 个球偏轻"或"第 i 个球偏重"，共 12×2 = 24 种等可能结果。
    需要信息 = log₂24 ≈ 4.585 bit
  2. 算每次称能给多少信息。天平有 3 种结果：左重、右重、平衡。
    每次最多提供 = log₂3 ≈ 1.585 bit
  3. 相除。4.585 / 1.585 ≈ 2.89 → 至少需要 3 次。

而 3 次最多提供 3×1.585 = 4.755 bit > 4.585 bit，信息量够用。所以 3 次可能做到——事实上确实存在 3 次的解法。

Corollary 推论

推广：若有 n 个球（不知轻重），需要 log₂(2n) bit，每次称提供 ≤ log₂3 bit，故

最少次数 k ≥ log₂(2n) / log₂3 = log₃(2n)

n=12 → k ≥ 2.89 → 3；n=13 → k ≥ 2.95 → 3；n=14 → k ≥ 3.02 → 4 次。
所以 13 个球是 3 次的极限。这个结论不需要试任何一种称法就能得到。

这就是信息论的威力 它给的是不可能性证明：不管你多聪明，2 次称球找不出 12 球中的次品。同样地，Shannon 定理告诉你不管编码多巧妙，压缩不可能突破熵、传输不可能突破容量。先划出边界，再谈方法——这是这门学科的思维方式。

Example 例题

英文的冗余度。Shannon 1951 年做过一个著名实验：让人猜英文句子的下一个字母，据此估计英文的实际熵约 1.0–1.5 bit/字母，而 26 个字母等概率时是 4.7 bit。

冗余度 = 1 − 实际熵/最大熵 ≈ 1 − 1.25/4.7 ≈ 73%

这解释了两件日常现象：
① 英文文本可以压缩到约 1/4 大小（ZIP 的物理基础）；
② "Ths sntnc s stll rdbl."（去掉元音仍可读）——冗余让语言抗噪。

Frontier 前沿

今天的大语言模型本质上就是在做 Shannon 1951 年那个"猜下一个字母"的游戏，只是猜的是 token，而且猜得极好。模型的训练目标交叉熵损失正是"平均每 token 的惊奇度"，而 困惑度 perplexity = 2^(交叉熵) 就是"模型觉得下一个词有多少种等可能选择"。
换句话说：压缩得越好 = 预测得越准 = 理解得越深。→ L4 大模型中的信息论

07自检与作业

Level 0 自检 · 答完再进 L1
  1. 为什么"信息量"要用对数，而不能直接用概率的倒数 1/p？
  2. 一个必然发生的事件，信息量是多少？为什么？
  3. 掷一枚均匀骰子，熵是多少 bit？如果骰子灌了铅，6 点出现概率是 1/2，其余各 1/10，熵会变大还是变小？
  4. 27 个球中有 1 个较重（已知偏重），用天平至少称几次？
  5. 如果一种语言的冗余度是 0，会发生什么坏事？
参考答案

1. 因为信息必须可加：两个独立事件的总信息量应等于各自之和。概率是相乘的（p₁p₂），只有对数能把乘法变加法。用 1/p 的话，两枚硬币会得到 4 而不是 2。

2. 0 bit。−log₂1 = 0。它没有消除任何不确定性。

3. 均匀骰子 H = log₂6 ≈ 2.585 bit。灌铅后 H = −[0.5·log₂0.5 + 5×0.1·log₂0.1] = 0.5 + 5×0.332 = 2.161 bit，变小。因为分布变得不均匀，结果更可预测了。均匀分布熵最大——这是 L1 的极值定理。

4. 已知偏重，只有 27 种可能，需要 log₂27 bit；每次称提供 log₂3 bit。27 = 3³，所以恰好 3 次（每次分三堆各 9 个）。

5. 冗余度为 0 意味着每个符号都携带满额信息，任何一个字符出错都无法察觉、无法纠正，且任何一段乱码都是合法句子。语言将完全不抗噪。自然语言的高冗余正是它能在嘈杂环境中沟通的原因，这也是 L2 信道编码定理的核心思想：刻意加入冗余来对抗噪声。

动手作业

  1. 统计你最近 100 条微信消息里表情符号出现的频率，算出这个"表情源"的熵。
  2. 用信息论论证：一次能问 4 种回答的"天平"（假设存在），找 12 球次品需要几次？
  3. 去 实验室 03 拖动三元分布的滑块，找出什么时候熵最大，验证你的猜想。
